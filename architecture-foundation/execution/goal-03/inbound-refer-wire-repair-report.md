# G03 Inbound REFER Wire Repair Report

Date: 2026-08-02

Scope: controlled G03 validation host only

Production eligibility: `false`

## Outcome

The first complete RustPBX library run exposed one deterministic inbound REFER
failure. The transfer INVITE contained two `Max-Forwards: 70` fields: one typed
singleton generated by rsipstack and one untyped field added by RustPBX. The G03
wire guard correctly rejected the duplicate singleton before parsing, so the
transfer target never received an `IncomingCall` event.

The repair removes RustPBX's duplicate field, leaves rsipstack authoritative for
the required singleton, and supplies an optional supplemental header vector only
when `Replaces` is present. A blind transfer therefore performs no supplemental
header-vector allocation. No parser relaxation, global lock, scan, task or
unbounded structure was added.
